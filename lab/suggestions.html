Suggestions — what to change, and in what order

Every improvement to this site and to this system, in one place, with the problem it solves, the evidence behind it, the cost, the risk and the recommendation. The point of this page is that a decision can be made before any code is written: read the list, tick the rows you want, and the build order follows.

How to use this page. The Recommendation column is this session's suggested path, not a decision. The Decision column in the review sheet below is where a reviewer records Accept, Defer or Reject with a note. Rows marked “already implemented in this release” need no decision — they are live on this site and can be reviewed on the page they point to.

Recommended build order

  1. Decide the two blockers. Q01 and Q05 on the decision register: which prices are legally accessible, and where historical lines come from. Nothing measurable can happen before these are answered.
  2. Ship the cheap site wins. P01 to P05, P13 — decision headers, a reachable flagged page, one filter box, per-table freshness, a vacation comparison view, and JSON beside every table.
  3. Automate the tracker. P12 — the injury and depth records are only useful if they refresh; the repository already refreshes schedule feeds from official endpoints in CI.
  4. Build the measurement layer. P11 — the quote and settlement archive, then backtests with the published gates, then the paper trial.
  5. Only then open the board. A strategy enters the leaderboard when it has cleared G0 to G8. Not before.
