How the line is made

A line is just a probability with the vig removed. This page shows exactly how the probability is produced, what data it uses, and how it performs out of sample. If a feature is missing for a game, it is set to a documented neutral value and the coverage table below shows how often that happens — the model never invents an input.

1 · Signals

Team strength (chronological Elo), recent form, rest differential, division flag, roof, quarterback continuity, and the injury/lineup shares. All are computed from games played before the one being predicted.

2 · Walk-forward fit

For each season, a logistic regression is fitted on every earlier season in the data and then predicts that season. Standardisation statistics come from the training seasons only. A unit test fails the build if a future row can be seen.

3 · Scoring

Log loss against a naive baseline built from prior-season home and away win rates. Accuracy and Brier are reported next to it. Skill = 1 − model ÷ baseline.

What a line-maker still needs

  • A price, not just a probability. Converting this probability into a line requires a vig and a market to compare with. The repository has one un-timestamped snapshot per game and no moneylines, so no price can be built without assuming a vig.
  • A decision cutoff. The injury report is published across the week; a usable line needs one fixed timestamp.
  • Player-level value. Snap share measures usage, not talent (see Q6).

NFL Lines Lab — every published number is generated from data fetched and hashed by the repository's own pipeline. No betting return, payout or edge is claimed anywhere: the only market data available is a single un-timestamped line snapshot, and no player-prop market exists in any reachable source.
