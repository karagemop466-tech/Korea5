Two of these datasets move between runs, by design. The injury page and the news index are live: each club's report is published on its own schedule, and the news pages that exist when CI runs are the news pages that get captured. Article and availability row counts therefore differ from one capture to the next — in the run before this one, 413 article rows and 32 club tables were found; in this one, fewer. The 132 games with FINAL scores did not move, and neither did the model's inputs that matter for the leaderboard. Numbers on these pages always come from the capture committed with them, and every capture is kept in git, so a figure can be traced to the run that produced it.

Why score binding is strict

A score is attached to a game only when it sits inside that game's own link block, or when the screen-reader label beside it agrees on both club nicknames. That check exists because a text window around a score can borrow a neighbouring card's number — the failure mode that quietly turns a backtest into fiction. Refusals are counted and published:

  • scoreLabelMismatches — []
  • perWeekFinal — weekly counts, so a parser regression shows up as a missing week instead of a plausible-looking season.
  • Five games (one club's cards render “Watch Replay” where the score label normally sits) stay null and are excluded from scoring; the exact markup around each is captured in official/lab/gap-context.json so any future fix is written against evidence.
  • The one attempt to recover those five from the game page itself reported gapFilledFromGamePages 0 — zero, because those pages carry no score either. Nothing was guessed to close the gap.

How to re-run it

gh workflow run nfl-lab.yml        # capture in CI (no outbound HTTP from the sandbox)
python3 tools/fetch_nfl_lab.py         # same code, locally, where HTTP is allowed
python3 scripts/signal_lab.py          # scores, gates, lines, forward ledger
python3 scripts/build_signals.py       # regenerate these pages
python3 scripts/check_links.py         # link/integrity gate for the whole site
python3 -m unittest discover tests -v  # maths and leakage tests

The CI commit step is if: always() and writes official/lab/error.txt, so a failed capture leaves a traceback in the branch instead of an empty commit — that is how the one run that reported zero scores was diagnosed rather than guessed at.

Framework, not just numbers. The research questions, gate design and reward proposal this build implements are written up in the NFL Lines & Strategy Lab. Requirement statuses live on the requirement ledger, and every decision taken about a suggestion is on the review board.
